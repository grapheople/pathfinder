# Query — 위키 기반 질의 응답

`CLAUDE.md`의 워크플로우 10.2(Query)를 그대로 수행한다. 이 문서가 규약과 어긋나면 CLAUDE.md가 우선이다.

## 사용자 입력

$ARGUMENTS

입력이 비어 있으면 짧게 질문을 요청.

## 절차

### 1. `index.md` 먼저 본다
카탈로그를 훑어 후보 페이지를 추린다. **무작정 grep하지 말고** index로 좁힌 뒤 본문을 읽는다.

### 2. 후보 페이지·인접 페이지 읽기
- 후보 페이지 본문을 읽는다.
- wikilink로 연결된 인접 페이지도 답에 필요한 만큼 따라간다.
- 도시 비교 질문이면 여러 `wiki/cities/`를, 카테고리 질문이면 `wiki/themes/`를 우선.
- 운영시간·가격 등은 POI 페이지 frontmatter·실용 정보 섹션을 본다.

### 3. 답한다 — 출처 인용 필수
- **답에 사용한 모든 위키 페이지를 `[[...]]`로 인용**.
- 사실 주장은 가능하면 `[[sources/...]]` 또는 `[[trips/.../content]]`까지 거슬러 인용.
- 위키에 없는 부분은 명시: **"위키에 없음, 일반 지식으로는 …"**.
- 모순되는 정보가 있으면 양쪽 진술을 나란히 보여주고 어느 출처가 더 신뢰할 만한지 의견 제시.
- 추측·환각 금지. 운영시간·가격은 1차 출처 없으면 비워두고 "확인 필요" 표시.

### 4. 페이지화 제안 (선택)
답이 **재사용 가치 있는 새 종합**이면(예: "벚꽃과 야경이 같이 좋은 도시 비교"):
> "이 비교를 위키에 새 페이지로 남길까요? `wiki/themes/<slug>.md`로 제안해요."

사용자 동의 시:
- 적절한 위치(주로 `wiki/themes/`)에 페이지 생성.
- frontmatter + 본문 + 출처 인용.
- 루트 `index.md` 반영.
- `log.md`에 `## [날짜] query→theme | <제목>` 엔트리.

### 5. log (페이지화한 경우만)
페이지화하지 않은 일반 query는 log에 남기지 않아도 된다(채팅으로 끝남). 페이지화하면 위 4단계대로 log 추가.

## 정상 종료 조건

- 답변에 출처 `[[...]]` 인용 포함
- 위키 외부 지식 사용 시 명시
- (선택) 페이지화 제안과 그 결과

## 마지막 보고

답변 본문 그 자체가 보고. 페이지화한 경우 마지막 줄에 생성 파일 경로를 명시.
